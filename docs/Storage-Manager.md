# Storage Manager

Open **Storage Manager** from the video editor's top navigation. Enter comma-separated keywords (for example `apple,orange`) and choose **Preview matches**. The scan checks all pages of the configured MinIO bucket. Matching is a case-insensitive substring search over the full object key, including folders and filename. Spaces are trimmed; empty and duplicate keywords are ignored. Files matching more than one keyword are assigned to the first keyword.

On opening the page, the taller, resizable keyword text area defaults to the same enabled language codes available to the translation controls via `/api/tts-audio-references`. English (`en`) is excluded, duplicates are removed, and the sorted codes are wrapped in underscores and separated by commas (for example `_eu_,_is_`). The list remains editable; loading defaults does not overwrite edits made while the request is pending. Preview and deletion still require manual actions.

Review file paths, counts, and sizes, then choose **Delete matched files** and confirm. Files and keywords are processed sequentially, with deleted, already missing, and failed counts. Individual failures do not prevent remaining files or keywords from being processed. **Stop after current file** stops future requests; it cannot undo finished deletions. Keep the page open while deleting. Refresh the preview to retry failed or stopped work.

Deletion permanently removes MinIO objects only. It does not delete or clear Baserow rows or fields. Existing references to removed files will stop working. With a versioned bucket, normal S3 deletion creates delete markers rather than purging historical versions; this page does not purge versions.

After a successful preview (including zero matches), Storage Manager sends one Telegram summary with keyword count, matched-file count, and matched size. After the entire deletion queue finishes, it sends one summary with deleted, already missing, and failed counts. Completed queues with failures are labeled accordingly; stopped queues do not send a completion notification. Notifications reuse `sendTelegramNotification` and `/api/notifications/telegram`, with the application's existing Telegram configuration. A notification failure shows a separate warning and does not change the storage operation's results.

The new `/api/storage-manager` route uses the existing `MINIO_BASE_URL`, `MINIO_BUCKET`, `MINIO_ROOT_USER`, and `MINIO_ROOT_PASSWORD` configuration. Credentials stay on the server. It uses signed S3 list, HEAD, and DELETE requests. Preview tokens are signed, scoped to the configured storage, and valid for deletion for one hour. When each file reaches the front of the deletion queue, its approval is automatically renewed if expired or within one minute of expiry. The `renew` action accepts an authentic signed preview even after expiry and issues a fresh one-hour token preserving the original key, ETag, size, and keyword. It never scans for additional matches or approves a changed file. Older previews without expiry metadata are renewed automatically too. If server timing still detects expiry (`409 APPROVAL_EXPIRED`), the client renews and retries that file once. Long runs therefore do not need another manual preview because of elapsed time. Invalid signatures and changed storage configuration remain rejected. Deletion checks each object's ETag and size against the original preview and skips changed files. No new environment variables, Baserow fields, or external services are required. The existing video-prefix and individual deletion routes remain unchanged.
